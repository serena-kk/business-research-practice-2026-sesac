# Iterative Refinement — 세그먼트·가설 재정의

> 5단계 검증에서 가설이 약하게 나왔다고 후보를 폐기하지 않는다. 핵심은 **공개자료로 검증되지 않은 가정을 걷어내고, 실제로 측정 가능한 문제 구조로 다시 좁히는 것**이다. A는 가설 방향을 유지하며 원인변수를 재정의, B는 고객 세그먼트와 문제변수를 상당 부분 다시 설계한다.

| 구분 | A. 중개사 Workflow Fragmentation | B. 구매자 Information Integration |
|---|---|---|
| 5단계 결과 | Weak | Not yet verifiable |
| 핵심 판단 | 문제 구조는 유지 가능 | 문제와 세그먼트 모두 재정의 필요 |
| 가장 큰 수정 | 전자계약 여부 → 실제 업무 분절 행동 | 생애최초 → 의사결정 복잡도를 만드는 행동·금융 특성 |
| 우선 변수 | Switching / Handoff / Duplicate Entry / Follow-up | 금융의존도 / 구매임박도 / 금융지식 / 정책금융 복잡도 |
| 측정 단위 | 거래 1건 | 주택 구매 의사결정 Episode |
| 시장분석 발전성 | 높음 | 중~높음 |
| 추천 순위 | 1순위 | 2순위 |

## A. Workflow Fragmentation × 개업공인중개사

**유지할 것.** ① 고객군(수도권 주거 중개를 반복 수행하는 개업공인중개사) — 정의가 명확하고 반복 업무 단위가 존재. ② 분석 단위는 중개사 개인이 아니라 **거래 1건**. ③ 결과변수는 "업무가 번거롭다"가 아니라 관찰 가능한 변수로 쪼갠다: Active Processing Time, System Switching Count, Duplicate Entry Count, Manual Handoff Count, Follow-up Check Count, Rework Count.

**수정할 것.** 가장 중요한 수정은 **전자계약 중심 사고를 버리는 것**이다. "비전자계약=비효율, 전자계약=효율"이라는 암묵적 구조는 공개자료로 증명되지 않았다. 독립변수를 `전자계약 사용 여부` → **`Workflow Fragmentation Level = f(Switching, Handoff, DuplicateEntry, Follow-up, Rework)`**로 바꾼다. 전자계약 여부는 독립변수가 아니라 설명·통제변수로 내려놓는다.

**제거해야 할 가정 4가지.**
1. 비전자계약 = 비효율 → 숙련된 중개사는 비전자 프로세스도 효율적으로 처리할 수 있다.
2. 전자계약 = 통합 Workflow → 전자계약을 써도 전후 단계에 별도 시스템·기관·채널이 남아 있을 수 있다.
3. 사용 시스템 수가 많으면 부담이 크다 → 자동 연동돼 있다면 시스템이 많아도 부담은 작을 수 있다. 중요한 것은 개수가 아니라 **전환+수동입력+수동전달**이다.
4. 모든 중개사가 같은 문제를 겪는다 → 거래량·거래유형·직원 수·디지털 숙련도에 따라 크게 달라진다.

**A 최종 문제 구조 (JTBD 형식)**

| 요소 | 내용 |
|---|---|
| Customer | 수도권 주거 중개거래를 반복 수행하는 개업공인중개사 |
| Context | 매물 확인부터 계약·신고·대출/보증 후속업무까지 복수의 시스템·기관·채널을 오가며 거래를 처리하는 상황 |
| Job-to-be-Done | 주거 중개거래 1건을 정확하고 누락 없이 완료한다 |
| Pain | 시스템 전환, 수동 전달, 동일정보 재입력, 처리상태 재확인이 반복되며 행정 처리시간과 재작업 증가 |
| Root Cause | 거래 단계 간 데이터·업무 연결이 충분하지 않아 정보와 책임이 시스템·기관·채널 사이에서 수동으로 이동 |

**정제된 A-H1**: "수도권 주거 중개거래에서 System Switching, Manual Handoff, Duplicate Entry, Follow-up Check가 많이 발생할수록 거래 1건당 Active Processing Time과 Rework가 증가한다." — 원인과 결과가 모두 관찰·측정 가능해 이전 버전보다 검증력이 높다.

## B. Information Integration Burden × 주택 구매자

B는 A보다 수정 폭이 크다. 핵심은 **'생애최초'가 문제를 설명하는 핵심 segmentation variable인지 자체가 아직 증명되지 않았다는 것**이다.

**유지할 것.** ① 문제의 중심(매물·실거래·호가·시세·대출·금리·LTV·DSR·정책대출·세금·자금계획을 함께 판단해야 함 — 정보 '부족'이 아니라 '결합과 해석'의 문제). ② Context(실제 구매 의사결정을 진행 중인 사람으로 범위 유지). ③ 결과변수(Decision Time, Cross-check Count, Information Source Count, Expert Consultation Count, Decision Reversal, Confidence).

**수정할 것.** 고객 기준을 `수도권 생애최초·실거주 구매자` → **`구매 의사결정 복잡도가 높은 수도권 실거주 구매 예정자`**로 바꾸고, 그 복잡도를 만드는 변수를 아래 우선순위로 재배치한다.

| 우선순위 | Segmentation Variable | 근거 |
|---:|---|---|
| 1 | **대출의존도(Financing Dependency)** | 동일 6억 주택도 현금5:대출1 vs 현금2:대출4는 LTV·DSR·금리·정책대출까지 동시 고려해야 하는 난도가 다름 |
| 2 | **구매 임박도(Purchase Imminence)** | 단순 관심 단계 사용자는 정보가 많아도 부담이 크지 않을 수 있음 |
| 3 | 금융지식(Financial Literacy) | DSR·금리유형·정책대출·취득세 이해도가 다르면 동일 정보의 부담도 다름 |
| 4 | 정책금융 이용 여부 | 디딤돌·보금자리론 등은 소득·자산·무주택·세대구성 등 검토 조건이 늘어남 |
| 보조 | 생애최초 여부, 연령, 가구형태, 주택가격, 지역, 주택유형 | primary segment가 아니라 control/descriptive variable로 하향 |

**제거해야 할 가정 4가지.**
1. 생애최초 구매자는 정보통합 부담이 높다 → 미검증. 대출의존도·금융지식이 더 설명력이 클 수 있다.
2. 정보원이 많을수록 부담이 크다 → 정보원 5개도 역할이 명확하면 부담이 크지 않을 수 있다. 중요한 것은 정보원 개수가 아니라 **서로 다른 정보를 직접 비교·변환·판단해야 하는 정도**다.
3. 정보 파편화가 판단 지연을 만든다 → 아직 인과 증거 없음. 원래 어려운 의사결정을 하는 사람이 정보를 많이 찾는 역인과 가능성.
4. 모든 생애최초 구매자는 동일한 문제를 겪는다 → 현금비중·금융지식·가격대·구매시점에 따라 크게 다름.

**B 최종 문제 구조 (JTBD 형식)**

| 요소 | 내용 |
|---|---|
| Customer | 수도권 실거주 주택 구매 예정자 중 금융조달 의존도가 높은 고객 |
| Context | 구매 후보 주택을 비교하고 실제 자금조달 가능성과 구매 가능 가격을 판단해야 하는 시점 |
| Job-to-be-Done | 내 재무조건과 후보 주택의 조건을 함께 고려해 구매 가능·적절 여부를 판단한다 |
| Pain | 주택가격·실거래·시세·대출·규제·정책금융·세금 정보를 각각 확인하고 개인 조건에 맞게 교차해석해야 해 판단시간·확인행동 증가 |
| Root Cause | 주택 정보와 금융·정책 정보가 서로 다른 기준·개인화 변수로 제공되어 사용자가 직접 연결·계산·검증해야 함 |

**정제된 B-H1**: "수도권 실거주 주택 구매 예정자 중 금융조달 의존도가 높은 고객에게서, 서로 다른 주택·금융·정책 정보를 직접 교차확인·계산해야 하는 정도가 높을수록 구매 판단시간, 정보 재확인 및 판단 번복이 증가한다."

## A vs B — Market Segment Map 발전 가능성 비교

여기서 **A가 한 단계 앞서 있다.** A는 Fragmentation↓Processing Burden 관계를 거래 단위로 즉시 측정할 수 있는 상태가 됐지만, B는 "어떤 세그먼트 변수가 burden을 가장 잘 설명하는지" 자체가 아직 미확정이다.

| | A에 적합한 1차 Segment Map 축 | B에 적합한 1차 Segment Map 축 |
|---|---|---|
| X축 | 거래량 / 업무 반복 빈도 (Low → High) | 구매 임박도 (정보탐색 → 후보비교 → 구매임박) |
| Y축 | Workflow Fragmentation (Low → High) | 금융조달 의존도 (Low → High) |
| 핵심 세그먼트 | 거래량 High × Fragmentation High | 구매임박도 High × 금융의존도 High |

**TAM-SAM-SOM 발전 가능성**

- **A**: `국내 주거중개 업무를 수행하는 개업공인중개사 → 수도권×주거용 중개(SAM) → 반복거래량·Fragmentation이 높은 중개사(SOM)`로 자연스럽게 내려간다. 시장 단위도 사업자 수·거래 건수로 명확하다.
- **B**: `주택 실수요 구매자 → 수도권 실거주 구매자(SAM) → 구매임박×금융조달의존도가 높은 구매자(SOM)` 구조는 만들 수 있으나, "금융조달 의존도가 높은 사람이 실제로 더 큰 Information Integration Burden을 겪는가"가 아직 검증되지 않아 **SAM→SOM 세분화 근거를 먼저 보강해야 한다.**

## 6단계 종료 시점 상태

| | 상태 |
|---|---|
| A | Problem-Segment Fit 가설이 충분히 정제됨 → **Market Segment Map 진행 가능** |
| B | Problem은 유지되나 Segment Fit 재검증 필요 → **Segment Discovery 추가 필요** |

따라서 다음 문서에서는 **A를 기준으로 Market Segment Map을 실제로 작성**하고, 4개 하위 세그먼트 중 어느 셀을 SAM/SOM으로 가져갈지 선정한다. B는 같은 방식으로 비교군을 만들되, '생애최초'를 SOM 조건으로 고정하지 않는다.
